# 缺陷检查报告

检查日期：2026年9月6日。

本轮检查覆盖计时状态切换、暂停与时长修改、智能分类取消与重试、待办存储与排序、周日程校验与保存、日历读取与刷新、声音播放与设置同步，并进行了签名构建和自动测试。保留了检查开始前已有的未提交改动。本报告不代表所有设备和使用场景均不存在问题。

## 已修复的问题

| 问题 | 触发与影响 | 修复与验证 |
| --- | --- | --- |
| 运行中切换阶段沿用旧计时基准 | 开始专注后切换休息，界面暂时显示休息时长，但暂停或下一次计时回调会恢复旧专注倒计时 | 切换前停止旧计时，再建立新基准；新增回归测试 |
| 修改休息时长清空暂停的专注进度 | 专注暂停时调整休息设置，会把剩余专注时间重置为完整时长 | 仅在当前阶段时长实际变化时更新倒计时；新增回归测试 |
| 暂停的休息不响应时长修改 | 短休息暂停后修改短休息时长，仍显示旧时长 | 将当前阶段的时长更新规则同时用于休息；新增回归测试 |
| 拖动等交互期间计时显示停顿 | 原计时器只注册在默认运行循环模式，事件跟踪期间不会触发刷新 | 改为主运行循环的通用模式；构建验证，持续拖动场景尚未人工实测 |
| 分类取消后重试被旧请求干扰 | 旧请求结束时可将新请求标记为结束并清空其任务引用，导致取消与状态异常 | 每次请求设置独立标识，检查标识后在同一主执行域内写入；新增交错完成回归测试；同时保留请求期间新输入的文本 |
| 日程设置修正后未保存 | 越界设置被修正到合法范围后提前返回，重启恢复的值与当前界面不同 | 修正后继续保存；扩展重载一致性测试 |
| 调整篝火参数后声音不更新 | 播放期间修改参数只清空缓存，正在循环的旧音频仍继续播放 | 参数变化且正在播放篝火时重新生成音频，复用已有代次校验拒绝旧生成结果；构建验证，听感尚未实测 |
| 全局玻璃透明度无法保存为零 | 用户将透明度设为零后，重启会被误判为“没有保存值”并恢复为默认透明度 | 改为检查设置项是否存在，保留合法的零值；新增回归测试 |
| 无有效音频输出格式时可能崩溃 | 音频设备缺失、切换异常或采样率无效时，创建单声道格式使用了强制取值 | 在创建音频引擎和缓冲区前校验采样率与格式，失败时安全停止播放 |
| 零时长计时可被重复完成 | 异常配置产生零时长时，多次开始会重复完成、增加专注次数并发送通知 | 零时长仅允许完成一次；新增回归测试 |
| 时间选择器响应窗口内无关滚动 | 原横向滚动监听覆盖整个应用窗口，指针不在时间选择器上也可能改变时长 | 监听器增加窗口与指针区域判断，并在视图移除时取消待执行回调和监听 |
| 异常系统数据可能触发强制取值崩溃 | 字形数组、时间标签数组及应用支持目录使用强制转换或强制取值 | 改为安全转换和后备路径，异常时保留可用界面 |

同时明确计时回调的主执行域约束，并清理测试中的执行域与异步加锁编译警告。

## 验证结果

- 全部76项单元测试通过，包括计时、智能分类、日程设置和零值持久化的回归测试。
- 静态分析通过，未报告代码缺陷。
- 应用及测试目标使用指定开发者证书构建成功。
- 应用严格签名验证通过，应用标识为 `xkzxing.PomodoroSwift`，身份要求基于固定开发者证书。
- 现有界面启动测试未完成：系统拒绝测试运行器访问其容器，运行器在测试连接建立前退出。此结果不能视为界面测试通过，也不能据此判定主应用启动存在缺陷。
- 差异空白检查通过。

## 验证边界

没有调用真实模型服务，没有替用户批准日历或其他系统权限，没有修改系统隐私数据库。系统休眠唤醒、通知操作、真实日历账户同步、音频设备切换与长时间交互仍需实际环境验收。

系统日历采用事件驱动刷新：日历数据发生变化、应用回到前台、日期或时区变化、来源选择变化、显示日期范围变化时才读取。时间线每分钟只更新当前时间指示，不读取系统日历。

本轮构建位于项目的 `build/BugAudit`，用于检查，没有覆盖已安装应用，没有生成或发布发行包。开发者签名不等于苹果公证。
